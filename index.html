nnnsightnnn · Tracker API

Public JSON data feeds from the trackers. Plug in or visit the site — both work.

Every nnnsightnnn tracker app publishes its underlying data as flat JSON files alongside the website. No API key, no auth, CORS open. If you want squad lists, news digests, or upcoming-game data for Liverpool FC, the Atlanta Falcons, Hawks, or Braves — fetch and go.

Stability: these are best-effort public data feeds. One developer running them as a side project. Schema-breaking changes get a 30-day notice in the changelog below and bump to v2; existing v1 paths keep responding for at least 90 days. No uptime SLA. No support contract. If you build something serious on top of these, mirror them locally.

URL scheme

https://nnnsightnnn.github.io/<tracker>/api/v1/<resource>.json

Each tracker exposes the same shape: a versioned v1 path with one JSON file per resource. index.json is always the manifest — fetch that first to discover what's available and when it was last refreshed.

Quick start

// JavaScript
const res = await fetch("https://nnnsightnnn.github.io/liverpool-tracker/api/v1/squad.json");
const squad = await res.json();
console.log(squad.find(p => p.position === "FWD" && p.status === "fit"));
# curl
curl https://nnnsightnnn.github.io/liverpool-tracker/api/v1/index.json | jq .
# Python
import requests
manifest = requests.get("https://nnnsightnnn.github.io/liverpool-tracker/api/v1/index.json").json()
for ep in manifest["endpoints"]:
    print(ep["resource"], ep["lastUpdated"])

Versioning

  • Additive changes — new endpoint or new field on an existing object — ship in v1, noted in the changelog below.
  • Breaking changes — rename, type change, removal — ship as v2 in parallel; v1 keeps responding for at least 90 days from cutover.
  • Each tracker versions independently. Liverpool's v2 doesn't force the others to bump.

Rate limits

None enforced — GitHub Pages CDN absorbs the traffic. Don't be ridiculous. If you're polling every second from a thousand users, mirror the JSON to your own storage. If usage ever forces a Cloudflare-in-front-of-Pages migration, that'll be announced here and won't change the URL scheme.
